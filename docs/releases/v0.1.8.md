# Aurora v0.1.8

本次更新将内置 UnityModManager 升级至 0.33.2，改进了首次使用向导和日志反馈功能，并修复了 modrift 部分资源无法打开的问题。

## 内置 UnityModManager 更新

内置 UMM loader 从 **0.32.5 升级至 0.33.2**。在首次使用向导中选择“使用内置内核”时，将安装这一版本。

## 首次使用向导

安装加载器时，向导会比较 ADOFAI Tools 提供的版本和 Aurora 内置版本，并给出建议：

- 资源站版本更新时，推荐从站点下载；
- 内置版本相同或更新，或站点没有可用版本、无法连接时，推荐使用内置内核；
- 未填写 API key 时，跳过站点查询，直接推荐内置内核。

推荐按钮会高亮显示，并说明原因。站点版本低于内置版本时，按钮也不再使用“获取最新”的表述，避免误导。

## 日志与反馈

日志现在默认开启，无需额外设置。遇到问题时，可以在“设置 → 关于 → 诊断与反馈”中：

- 打开日志文件夹；
- 导出诊断包，将日志、环境信息和脱敏后的设置打包为 ZIP；
- 打开反馈页面。

API key、下载签名和 token 等信息会在写入日志前替换为 `***`。单份日志上限为 2 MB，达到上限后会切换到新日志，并保留上一份。

崩溃日志 `crash.log` 新增软件版本、系统和安装类型信息，方便排查。日志也可以在“设置 → 关于”中关闭，关闭后仅保留崩溃日志。

## 来源标注

“在线 Mod”页面会显示当前来源，并提供对应站点的链接。

TUF 来源会注明“Mod 数据与推荐由 TUF（The Universal Forums）提供”；ADOFAI Tools、modlist 和 modrift 也会标注对应站点。

## 问题修复

### modrift 中部分资源打开时报 404

modrift 除 Mod 外，还收录资源包、预设、着色器和插件等内容。此前 Aurora 将这些条目都按 Mod 请求，导致部分资源（例如 Nexus's Keyviewer）打开时报 404。

现在会按资源的实际类型请求。对于非 UMM Mod 的资源，会显示类型说明，并提供原站页面入口供用户手动下载，不再显示不适用的安装按钮。

## 升级方式

使用 v0.1.6 或更高版本的用户，可以在软件内点击“立即更新”。也可以退出软件后手动升级：

| 版本 | 操作 |
| --- | --- |
| 安装版 | 运行 `Aurora-Setup-0.1.8.exe`，覆盖安装 |
| 绿色版 | 将 ZIP 解压并覆盖到原来的程序目录 |

> v0.1.5 及更早版本的自动更新存在问题，请手动下载安装包覆盖安装，或解压 ZIP 覆盖原程序目录。

原有设置、收藏和日志会保留。升级前建议备份游戏目录中的 `Mods` 文件夹。
