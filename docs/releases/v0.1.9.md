# Aurora v0.1.9

本次更新修复了一个可能影响游戏目录的 Mod 安装问题（**建议所有用户更新**），修正了更新检查的若干误判，并让 Mod 简介支持 Markdown 排版。

## 安装与卸载更安全

- **拒绝异常的文件名（建议所有用户更新）**：某些 Mod 包里的 `Info.json` 带有不合法的 Id（例如 `..`），此前可能把文件写到 `Mods` 目录之外，极端情况下会影响到游戏目录。现在这类包会被直接拒绝安装。
- **先准备好，再替换旧版本**：安装时先把整个包装到临时目录，成功后再替换旧版本。压缩包损坏或文件被占用时，原来的版本不受影响，不会再留下半个 Mod。
- **游戏运行时不允许改动**：游戏开着的时候不再允许安装、卸载、启用/禁用 Mod，也不允许部署或卸载加载器 —— 这些操作会因为文件被占用而失败，改动也可能在游戏退出时被覆盖。现在会提示先关闭游戏。
- **中断的安装可以恢复**：安装过程中如果被强制关闭或断电，残留的临时文件会在下次启动时清理；如果留下的是旧版本备份，会自动恢复回去，不会把 Mod 弄丢。
- **卸载加载器不再误删别人的文件**：电脑里可能同时装着 BepInEx 等其它加载器，它们同样会用到 `winhttp.dll` / `doorstop_config.ini`。现在只删除确实由 Aurora 写入的文件，其余保留并在结果里说明。

## 更新检查

- 修复资源站的更新提示全部显示「版本号规则不同」的问题（参数传反了）。
- 资源站忽略分页参数时，更新检查不会再无限请求。
- 网络不可用时，「检查全部」不再为每个 Mod 重新等待一遍超时。
- `Repository.json` 里列了多个 Mod 时，不再拿别的 Mod 的版本号，避免误报更新。
- 仓库地址只去掉结尾的 `.git`；GitHub 更新改用与其它来源一致的版本比较规则。
- 修正 `1.0.0.5` 被显示成 `1.0.5` 的问题。
- 从资源站重装 Mod 时，不再覆盖手动绑定的更新源；启动时也不会因为“自动检测得分更高”就改掉你手动选择的游戏目录。

## 界面与性能

- 修复详情页的竞态：图标加载期间切换到别的 Mod 时，旧 Mod 的版本列表可能盖到新 Mod 上。
- 已卸载的 Mod 不会在在线列表中继续显示「已安装」。
- 列表后台补页时只加载新增条目的图标，不再是每补一页就把整个列表重刷一遍。
- 「已安装」页：连点更新按钮不会重复触发；检查更新失败会给出提示，而不是毫无反应。
- 图标下载失败后 3 分钟内会自动重试，不必重启软件。
- 游戏版本读取加了缓存，刷新列表不再反复读取几 MB 的文件。
- 配置、收藏、安装记录和更新源改为原子写入；配置文件损坏时会先备份为 `settings.json.broken`，再使用默认配置。
- 界面线程上未处理的异常不再直接闪退：会记录日志并弹窗提示，可以继续使用（建议重启一次）。

## Mod 简介支持 Markdown

- Mod 简介和每个版本的更新说明现在会按 Markdown 排版：标题、加粗、列表、代码、引用、表格、链接和图片。
- 字体、字号和行距与界面其它文字保持一致。
- 超长的说明会自动截断；纯 HTML 写的说明会回退为原文显示，不会变成空白。

## 升级方式

使用 v0.1.6 或更高版本的用户，可以在软件内点击“立即更新”。也可以退出软件后手动升级：

| 版本 | 操作 |
| --- | --- |
| 安装版 | 运行 `Aurora-Setup-0.1.9.exe`，覆盖安装 |
| 绿色版 | 将 ZIP 解压并覆盖到原来的程序目录 |

> v0.1.5 及更早版本自带的自动更新存在问题，请手动下载安装包覆盖安装，或解压 ZIP 覆盖原程序目录。

原有设置、收藏和日志会保留。升级前建议备份游戏目录中的 `Mods` 文件夹。
