# Aurora v0.1.10

本次更新修正了内核更新提示的判断逻辑，并把 Mod 更新改成了覆盖安装，避免更新时丢掉 Mod 自己的配置。

## 内核更新提示

### 现象

v0.1.8 和 v0.1.9 已经把内置的 UnityModManager 内核从 0.32.5 升级到 0.33.2，但打开软件后不会提示更新内核。

### 原因

「检查内核更新」此前只比较「资源站上的内核版本」和「已部署的版本」。而资源站上的内核由站长单独维护，没有跟着软件一起更新（目前站点上仍是 0.32.5），于是软件一直认为已经是最新。

### 现在

- **UMM 环境页**：内置内核比已部署的新时，会直接显示提示，写明两个版本号和操作路径（安装 / 修复加载器 → 使用内置内核）。
- **「检查内核更新」**：同时比较「资源站版本」和「内置版本」，取更高的那个：
  - 站点不可用（未填写 API key，或连不上）时，也能只靠内置内核给出判断；
  - 胜出的是内置内核时，直接本地部署，不需要下载。

## Mod 更新改为覆盖安装

### 现象

更新某些 Mod 之后，Mod 自己的设置会被重置。

### 原因

此前的更新方式是：把旧文件夹整个换掉，再放入新版本。Mod 写在自身文件夹里的配置文件（各种 json、预设、子目录）会随旧文件夹一起消失，只有 `Settings.xml` 被单独保留下来。

### 现在

更新时：

1. 先把旧版本的内容保留下来；
2. 再用新版本覆盖上去。

因此 Mod 自己的配置、预设和其它文件都会保留，包内同名文件则正常更新为新版本；安装失败时仍可回滚。

> 需要说明的是：新版本中已经删除的文件不会跟着删除，这是覆盖安装的固有代价。如果更希望「以新包为准、只保留配置文件」，可以反馈，我们会再调整。

## 升级方式

使用 v0.1.6 或更高版本的用户，可以在软件内点击“立即更新”。也可以退出软件后手动升级：

| 版本 | 操作 |
| --- | --- |
| 安装版 | 运行 `Aurora-Setup-0.1.10.exe`，覆盖安装 |
| 绿色版 | 将 ZIP 解压并覆盖到原来的程序目录 |

> v0.1.5 及更早版本自带的自动更新存在问题，请手动下载安装包覆盖安装，或解压 ZIP 覆盖原程序目录。

原有设置、收藏和日志会保留。升级前建议备份游戏目录中的 `Mods` 文件夹。
