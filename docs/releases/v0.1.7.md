# Aurora v0.1.7

本版新增 modrift 资源站，并重做了在线 Mod 列表的加载方式：切换来源时先显示上次的结果，再在后台补全并显示进度。同时修复了鼠标停留在链接上滚动会让程序崩溃的问题。

## 新增来源：modrift

- 在“在线 Mod”的来源列表中新增 **modrift**，位置在 ADOFAI Tools 之后。
- 无需 API key，免登录即可浏览和安装；国内可直连。
- 支持查看 Mod 介绍、选择版本安装，并按当前游戏版本自动选择合适的文件。
- 该站点允许发布没有文件的版本，Aurora 会自动跳过，避免下载到空内容。

## 在线 Mod 列表加载改进

### 先显示上次的结果，再后台刷新

打开或切换来源时，若之前浏览过，会**立刻显示上次的列表**，再在后台刷新。刷新失败时会保留已经显示的内容，并提供“重试”，不用再对着空白列表等站点响应。

### 显示“已加载多少”

加载过程中，副标题会显示进度，例如：

```text
ADOFAITools 共 125 个资源，已加载 60 / 125（后台补全中…）
```

首屏出现后，后面的分页会在后台陆续补齐，滚动到底部不会“就此停住”。

### Mod 详情也会缓存

点过的 Mod，其详情会保存在本地，再次点击立即显示，随后再刷新。首次加载（没有缓存）时会显示“正在加载 mod 详情…”。

## 问题修复

### 鼠标停留在链接上滚动会让程序崩溃

当鼠标指针停留在文字里的链接（例如 Mod 简介中的网址）上滚动滚轮时，程序会抛出异常并崩溃。本版已修复。

### 加载中切换来源，界面会被上一个来源抢回去

在某个来源还在加载时切换到另一个来源，前一个来源的结果回来后会覆盖当前界面。现在切换来源会取消上一次请求，其结果也会被丢弃。

### 图标有白色光晕、且比其它程序略小

图标外圈残留了一圈半透明的白色（在深色桌面和任务栏上呈白色光晕），本版改为完全透明；同时按内容边界重新裁切，图标不再比其它程序小一圈。

> 桌面上已有的快捷方式可能仍是旧图标（Windows 会缓存），删除后重新创建即可。

### 第三方来源的等待时间

第三方来源（TUF、modlist 等）的请求超时由 60 秒调整为 30 秒。站点较慢时会更快给出失败提示，并退回上次的缓存，不再“卡满一分钟”。

## 其他改进

### 启动后更早提示 Aurora 自身的新版本

启动时会依次检查 Aurora 自身更新和已安装 Mod 的更新。此前先检查 Mod —— 需要查询所有已配置的来源，站点较慢时要几十秒，导致“Aurora 有新版本”的提示条很晚才出现。现在先检查自身更新（通常两秒内出结果），再检查 Mod 更新。

### 不会再误把名字相近的工具当成 Aurora

资源站工具库里的身份判断此前比较宽松（为兼容原名 AMM），会把名字为 `AMM` 或以 `AMM` 开头的工具也当作 Aurora，可能提示并不存在的“新版本”。现在只认可确认属于本项目的名称和标识。

## 升级方式

使用 v0.1.6 或更高版本的用户，可以在软件内点击“立即更新”。也可以退出软件后手动升级：

| 版本 | 操作 |
| --- | --- |
| 安装版 | 运行 `Aurora-Setup-0.1.7.exe`，覆盖安装 |
| 绿色版 | 将 ZIP 解压并覆盖到原来的程序目录 |

> **还在 v0.1.5 或更早的版本，请手动升级**：
>
> - **安装版**：这些版本自带的自动更新会把安装包误当成压缩包解压，报
>   “End of Central Directory record could not be found”。问题在 v0.1.6 已修复，
>   但旧版本自身的更新器仍然是坏的。
> - **绿色版**：v0.1.5 及更早的更新程序会按旧的文件名重启程序，替换不完整。
>
> 两种情况都请手动升级：运行 `Aurora-Setup-0.1.7.exe` 覆盖安装，或解压 ZIP 覆盖原程序目录。

原有设置、收藏和日志会保留。升级前建议备份游戏目录中的 `Mods` 文件夹。
